## 2. Database — ERD, schema, indexes, rapid-tap strategy

### ERD
```
users 1───∗ bill_entries ∗───1 items
  │            │
  │            └─ (user_id, item_id, bill_date) UNIQUE  ← atomic upsert target
  │
  └──∗ activity_logs (actor / target_user)
```
Better Auth also manages `session`, `account`, `verification` (its own tables, generated).

### Drizzle schema notes (key reconciliation with the spec)
- **`users`**: Better Auth owns the core user table; we extend it with `additionalFields`: `role` (enum `USER`/`ADMIN`, default `USER`), `isActive` (default true), `lastActiveAt`. The spec's `password_hash` is **replaced** by Better Auth's `account` table (credential provider stores the hash) — no manual hashing.
- **`items`**: `id, name, price (numeric 12,2), icon (emoji, nullable), createdBy→users, isActive, lastUsedAt, createdAt, updatedAt, shopId (nullable, future)`.
- **`bill_entries`** (the heart): `id, userId, itemId, quantity, unitPrice (snapshot), subtotal, consumedAt (timestamptz default now()), billDate (DATE GENERATED ALWAYS AS (consumed_at::date) STORED), createdAt, updatedAt`.
  - `unitPrice` is a **snapshot** — historical rows never recompute from `items.price`.
- **`activity_logs`**: as spec (`actorId, targetUserId, entityType, entityId, action, oldValue jsonb, newValue jsonb, createdAt`).

### Indexes
- `UNIQUE (user_id, item_id, bill_date)` on `bill_entries` → powers the atomic upsert.
- `idx_bill_entries_user_date (user_id, consumed_at DESC)`
- `idx_bill_entries_item (item_id)` · `idx_items_recent (last_used_at DESC)` · `idx_activity_created (created_at DESC)`
- `idx_items_active (is_active, last_used_at DESC)`

### Rapid-tap safety (the hardest requirement) — atomic upsert
Every `addItemToBill` runs **one** atomic statement:
```sql
INSERT INTO bill_entries (user_id, item_id, quantity, unit_price, subtotal, consumed_at)
VALUES ($uid, $itemId, 1, $price, $price, NOW())
ON CONFLICT (user_id, item_id, bill_date)
DO UPDATE SET quantity  = bill_entries.quantity + 1,
              subtotal  = bill_entries.subtotal + EXCLUDED.unit_price,
              updated_at = NOW()
RETURNING *;
```
10 rapid taps ⇒ 10 atomic `+1`s ⇒ final quantity exactly 10. No client read-modify-write. Postgres serializes conflicts on the same row safely.

## 3. Authentication (Better Auth)
- `src/lib/auth/auth.ts` — Better Auth instance, Drizzle adapter, credential provider, `additionalFields { role, isActive, lastActiveAt }`.
- `src/lib/auth/server.ts` — `getSession()` (headers()), `requireUser()`, `requireAdmin()`.
- `src/lib/auth/client.ts` — `authClient` (signIn/signUp/signOut).
- Route handler: `src/app/api/auth/[...all]/route.ts` mounts the Better Auth handler.
- **Admin bootstrap**: `databaseHooks.user.create.before` checks `process.env.ADMIN_EMAILS` (comma-sep) and sets `role='ADMIN'` if the email matches.
- **Middleware** (`src/middleware.ts`): protect `/(user)/*` (redirect to `/login` if no session); protect `/admin/*` (redirect non-admins to `/home`); public: `/(auth)/*`, `/`, assets.
- Password hashing, session cookies, CSRF — all handled by Better Auth (no hand-rolled crypto).

## 4. State-management architecture (Zustand bill store)
`src/stores/bill-store.ts` — client UI state only, **not** the DB.

Design (production-grade improvements over the spec's example):
- **Derived total** via a selector (`useBillTotal()`), not stored — eliminates total/items drift.
- **Hydration**: `hydrate(authoritativeItems)` loads today's bill from the server on mount.
- **Optimistic mutation tracking**: `inFlight: Record<itemId, number>` counts pending taps per item.
  - Displayed qty = `serverQty + optimisticDelta`.
  - On response: decrement `inFlight`, set `serverQty` to authoritative value (out-of-order safe).
  - On error: roll back the optimistic delta, surface a "Couldn't save that tap — Retry" toast; never silently drop.
- Actions: `addItem(item)`, `decreaseItem(itemId)`, `removeItem(itemId)`, `clearBill()`, `hydrate()`.
- Selectors (memoized) for `useTotalQuantity`, `useTotalAmount`, `useBillItems`.

## 5. Data flow — single tap
```
1. Tap ItemCard
2. Zustand: optimistic qty+1, +1 float animation, total animates (Motion, ~150–250ms)
3. Fire Server Action addItemToBill(itemId)  (no await blocking UI)
4. Server: getSession → Zod → fetch item (price snapshot) → atomic upsert → activity_log
5. Return authoritative {itemId, quantity, unitPrice, subtotal}
6. Client reconciles (inFlight--, serverQty = response) — UI already matches
   On failure: rollback + retry toast
```
Items are **never** awaited before showing feedback.

## 11. Security checklist
Server-derived identity · role checks on every mutation · Zod on all inputs · Drizzle parametrized queries (SQLi-safe) · secrets server-only (`DATABASE_URL`, `AUTH_SECRET`, `BETTER_AUTH_SECRET` never to client) · httpOnly secure cookies (Better Auth) · audit logging on all admin mutations · input limits · rate limiting on auth + write actions.
