
# TapShop Performance Optimization Plan

## Problem
Every page navigation takes ~5 seconds with a blank screen. The root cause is multiple redundant DB round-trips per navigation through the Neon HTTP driver (no connection pooling), combined with no streaming/loading UI.

## Approach: Multi-Layered Optimizations (9 changes, ordered by impact)

---

### 🔴 HIGH IMPACT

#### 1. Eliminate Duplicate Auth Calls (`proxy.ts` + layout `requireUser()`)
**Problem:** Every protected page calls `auth.api.getSession()` TWICE — once in `proxy.ts` and once in `(user)/layout.tsx`'s `requireUser()`. Both make identical DB queries.
**Fix:** In `proxy.ts`, attach the validated session to a request header (e.g., `x-session-verified`). In `requireUser()` and `getSession()`, read from this header instead of re-querying the DB. This eliminates 1 full DB round-trip per navigation.
**Files:** `src/proxy.ts`, `src/lib/auth/server.ts`

#### 2. Add `loading.tsx` Files for Instant Perceived Performance
**Problem:** Zero loading files exist. Users see a blank white screen until all DB queries complete. `BillingScreenSkeleton` is already written but never used.
**Fix:**
- Add `src/app/(user)/loading.tsx` — show skeleton with header + bottom nav + pulsing content area
- Add `src/app/(admin)/loading.tsx` — same pattern for admin routes
- Use the existing `BillingScreenSkeleton` component
- Optionally wrap individual page data fetches in `<Suspense>` with lighter per-page skeletons
**Files:** New `src/app/(user)/loading.tsx`, new `src/app/(admin)/loading.tsx`, potentially `src/app/(user)/stats/loading.tsx`, `src/app/(user)/activity/loading.tsx`

#### 3. Use Neon Serverless Driver with Connection Pooling (`@neonatabase/serverless` pooler mode)
**Problem:** The Neon HTTP driver makes a separate HTTP connection for every single SQL query. The Stats page fires 7 parallel queries = 7 separate HTTP connections from a cold Vercel serverless function. Pages with more queries (Admin Dashboard: 8 queries) are even slower.
**Fix:** Enable Neon's pooler by switching the `DATABASE_URL` to the pooler connection string (uses `-pooler` host endpoint that Neon provides). This multiplexes queries over fewer connections. Also consider using `@neondatabase/serverless`'s `Pool` or `Client` with `pg` adapter instead of raw HTTP for query batching.
**Files:** `src/db/index.ts`, `.env.local` / Vercel env config

---

### 🟡 MEDIUM IMPACT

#### 4. Optimize Stats Page: Reduce 7 Queries → 2 Queries
**Problem:** `getStats()` fires 7 separate parallel queries (todaySpend, yesterdaySpend, weekSpend, monthSpend, itemsTapped, mostUsed, weekly). Each is a separate HTTP request to Neon.
**Fix:** Consolidate into 2 queries:
- **Query 1:** A single aggregated SELECT that computes todaySpend, yesterdaySpend, weekSpend, monthSpend, itemsTapped using conditional aggregation (`SUM(CASE WHEN bill_date = CURRENT_DATE THEN subtotal END)`, etc.)
- **Query 2:** Keep the weekly GROUP BY as-is (different shape)
- Drop `mostUsed` from the initial page load (fetch it client-side or lazily)
**Files:** `src/lib/services/stats.ts`

#### 5. Remove Unnecessary `"use client"` Directives
**Problem:** `AdminHeader` and `DashboardScreen` have `"use client"` but use zero hooks or client APIs. This forces unnecessary client JS bundles for admin routes.
**Fix:** Remove `"use client"` from `src/components/admin/admin-header.tsx` and `src/components/admin/dashboard-screen.tsx`.
**Files:** `src/components/admin/admin-header.tsx`, `src/components/admin/dashboard-screen.tsx`

#### 6. Configure `next.config.ts` for Production
**Problem:** The config is completely empty. No caching headers, no image optimization, no compression settings.
**Fix:** Add basic production optimizations:
```ts
const nextConfig: NextConfig = {
  compress: true,
  poweredByHeader: false,
  images: {
    formats: ["image/avif", "image/webp"],
  },
  experimental: {
    optimizeCss: true,  // if applicable
  },
};
```
**Files:** `next.config.ts`

---

### 🟢 LOW IMPACT (Nice-to-Have)

#### 7. Replace `motion` on BillItemCard with CSS Transitions
**Problem:** Every item card in the grid uses `motion.div` with `whileTap={{ scale: 0.95 }}`. This imports the entire `motion` runtime (~25-30KB gzipped) for the most performance-critical page.
**Fix:** Replace with CSS `active:scale-95 transition-transform` (already available in Tailwind). Keep `motion` only for `AnimatedTotal` (imperative tween) and `profile-view.tsx` (AnimatePresence for modals).
**Files:** `src/components/billing/bill-item-card.tsx`, `src/components/billing/recent-taps.tsx`

#### 8. Pause Stats Polling When Tab is Hidden
**Problem:** `StatsProvider` polls `GET /api/stats` every 60 seconds even when the tab is not visible, wasting resources.
**Fix:** Add a `visibilitychange` event listener that pauses/resumes the interval.
**Files:** `src/components/stats/stats-provider.tsx`

#### 9. Fix Admin User Details: Duplicate `getAdminUserDetails()` Calls
**Problem:** In `src/app/(admin)/users/[id]/page.tsx`, both `generateMetadata()` and the page component call `getAdminUserDetails(id)` separately — the same 5 queries run twice.
**Fix:** Use React's `unstable_cache()` or the page's data as the metadata source to avoid the duplicate queries.
**Files:** `src/app/(admin)/users/[id]/page.tsx`

## Expected Impact Summary

| Change | Estimated Time Saved | Effort |
|--------|----------------------|--------|
| Eliminate duplicate auth | -1 DB round-trip per nav | Small |
| Add loading.tsx | Instant perceived feedback | Small |
| Neon connection pooling | -30-50% DB latency | Small |
| Consolidate stats queries | -5 HTTP requests on Stats page | Medium |
| Remove unnecessary "use client" | Smaller JS bundle for admin | Trivial |
| next.config.ts optimizations | Better caching/compression | Small |
| Replace motion with CSS | -25-30KB from home page JS | Small |
| Pause tab-hidden polling | Saves background resources | Trivial |
| Fix admin duplicate queries | -5 DB calls on user details | Small |

**Total estimated improvement: ~40-60% faster page transitions** with the biggest wins from eliminating duplicate auth, adding loading UI, and enabling connection pooling.
