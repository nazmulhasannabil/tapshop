# Plan: Save Bill (datewise) + paginated Saved Bills table on Activity

## Goal
Let the user deliberately **save a snapshot of today's bill** (items + total) to the database, then review all saved bills in a **paginated table** on the Activity page (replacing the current item-tap timeline). Saving is **non-destructive** — the live "Today's Bill" keeps accumulating; multiple saves per day are allowed.

Data source of truth for a save = the server-side `bill_entries` for today (not client state), so the snapshot is tamper-proof and consistent.

---

## 1. New DB table — `saved_bills`

**New file:** `src/db/schema/saved-bills.ts`

```
saved_bills
  id          text pk (crypto.randomUUID)
  user_id     text notNull → users.id (cascade)
  bill_date   date notNull default CURRENT_DATE   (the day the bill is for)
  total       numeric(12,2) notNull
  item_count  integer notNull                      (sum of quantities)
  items       jsonb notNull                         (snapshot array, see type below)
  created_at  timestamptz notNull default now()
indexes: (user_id, created_at desc)  — powers the paginated table query
(no unique constraint — multiple saves per day allowed)
```

`items` jsonb mirrors the existing `activity_logs.old/new_value` jsonb pattern (so this is an established convention here). Shape per item: `{ name, icon, unitPrice, quantity, subtotal }`.

**Modify:** `src/db/schema/index.ts` — import/export `savedBills` + `SavedBill` type, add `savedBillsRelations` (→ users) and a `savedBills` entry on `usersRelations`.

## 2. Shared types — `src/types/bill.ts` (add)

```ts
export type SavedBillItem = { name: string; icon: string | null; unitPrice: number; quantity: number; subtotal: number };
export type SavedBill = { id: string; billDate: string; total: number; itemCount: number; items: SavedBillItem[]; createdAt: string };
export type SavedBillSummary = { id: string; billDate: string; total: number; itemCount: number; createdAt: string };
export type SaveBillResult = { id: string; billDate: string; total: number; itemCount: number; createdAt: string };
export type Paginated<T> = { items: T[]; page: number; pageSize: number; total: number; totalPages: number };
```

## 3. Service layer — new `src/lib/services/saved-bills.ts`

- `saveTodayBill(userId): Promise<SaveBillResult>` — reuse `getTodayBill(userId)` from `billing.ts`; if empty throw `BillingError("EMPTY_BILL", ...)`. Build `{ total, itemCount, items }` from the lines, `INSERT` into `savedBills`, return summary. (Mirrors `num()` coercion used elsewhere.)
- `getSavedBills(userId, page, pageSize): Promise<Paginated<SavedBill>>` — `ORDER BY created_at DESC`; two queries: a `count(*)` for totals + a page query with `LIMIT/OFFSET`. Clamp `page ≥ 1`; `totalPages = max(1, ceil(total/pageSize))`.
- Re-export/extend `BillingError` from `billing.ts` (import it — already exported).

`PAGE_SIZE` constant (e.g. `10`) lives here and is imported by the page + table.

## 4. API route — new `src/app/api/bill/save/route.ts`

`POST /api/bill/save` following the exact pattern of `bill/add/route.ts`:
`getSession()` auth → no body needed → `saveTodayBill(session.user.id)` → `ok(result)` / `fail(...)`. Returns 400 on empty bill, 401 unauth, 500 otherwise.

## 5. Client hook — new `src/hooks/use-saved-bills.ts`

`useSavedBill()` → `saveBill(): Promise<ApiResult<SaveBillResult>>` using the same `postJson` pattern as `use-bill.ts` (POST `/api/bill/save`, `credentials: "include"`). Toasts on success ("Bill saved") and error. No optimistic store change needed (live bill is untouched).

## 9. Edge cases handled
- **Empty bill:** Save button disabled in `SaveBillSheet`; server also returns 400 (defense in depth).
- **Out-of-range pages:** `page` clamped to `≥1`; table shows empty state beyond last page; `totalPages ≥ 1`.
- **Non-numeric / missing `?page`:** defaults to 1.
- **Concurrent saves same second:** each is its own row (uuid pk), no unique constraint — safe.
- **Price drift:** the snapshot uses today's `bill_entries.unitPrice` snapshots (already correct), frozen in jsonb forever.
- **Next 16 caveat:** per `AGENTS.md`, I'll keep the page a Server Component using the async `searchParams` + `PageProps` helper verified from `node_modules/next/dist/docs/`.
